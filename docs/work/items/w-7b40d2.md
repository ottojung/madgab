# w-7b40d2 — make the shortlist fill respect the cost bands it already builds

Front: the **contents** of a span's shortlist. The per-slot enumeration cap
(`affordable_opening_width`, `LEXICAL_BRANCH_STAGE_0`) and the walk over
`slots[k]` belong to other fronts and are untouched here.

Recommendation: **HOLD**. The change does what it was asked to do, by a
wide margin, and it costs one of the three `approximate_pool_reaches_*`
guards. The guard is not re-pinned and the tension is priced below with
the one line a successor front has to change.

## 2. The change

`src/lib.rs`, no behaviour outside the shortlist rule:

* the six admission passes are lifted out of `generate_approximate` into
  `Generator::span_shortlist`, unchanged, and the production loop calls it;
* the **fill** is no longer a walk of the global `quality` order. Its slots
  are apportioned over the cost bands in proportion to band population
  (highest average per-slot weight first, which is the integral form of a
  population-proportional apportionment, ties by band index) and spent
  **within a band** by `quality`;
* the fill stops early only when every band's unclaimed words are spent,
  so the list is still filled to `SPAN_SHORTLIST`;
* `SPAN_AXIS_KEEP`, `SPAN_BAND_KEEP`, `SPAN_RARITY_KEEP` move from
  function scope to module scope with their values untouched, so the rule
  can be reached from the new public API;
* new public API at the boundary: `SpanCandidate`, `span_candidates` (what
  a span offers) and `span_shortlists` (what it retains), both a pure
  function of `(target, per_word_budget)`.

Keyed only on measured properties — band population, cost, quality. No
clue, sentence or word list anywhere in the change, and
`git grep -i -E "wreck|beach|recognize|justice|stupid|dupe|came|hid" -- src`
returns only the pre-existing `#[cfg(test)]` fixtures, CLI usage examples
and ordinary English comments (verified on this branch; the change adds no
hit).

## 3. The regression test

`tests/span_shortlist_bands.rs`, three tests over twelve real targets, at
the public API boundary:

1. **every non-empty cost band contributes to the span shortlist** — the
   general property. Band edges are **re-derived inside the test** as the
   three interior cuts of four equal-width bands over *the span's own
   observed cost range*, not read from the rule's axis, so a future change
   to that axis cannot make the assertion vacuous. 885 spans, **3,234
   non-empty bands, 0 unrepresented.**
2. **every non-empty cost band keeps a word near the span cheapest** — the
   same partition, restricted to candidates within 1.5x of the span's
   cheapest: **1,371 populated competitive bands, 0 unrepresented.**
3. **the shortlist width is unchanged** — no span retains over 160, and no
   span retains a word it did not offer, so the per-span alternative count
   the DP relaxes over is the same bound as before.

Tests 1 and 2 are **discriminating, not decorative**: with the new API and
the *old* fill restored, the same survey reports **1 unrepresented band of
3,234** (test 1) and **2 of 1,371** (test 2). With the stratified fill
both are 0.

One honest caveat, recorded rather than hidden: the property is stated on
bands the *test* derives. Under a **population**-quartile partition of the
same costs instead of an equal-width one, 10 of 3,048 bands are
unrepresented **after** the change (1 of 3,048 before) — the tail bands by
population can be wholly inside the region a population-proportional fill
treats as one thin slice. The equal-width partition is the one stated in
the test and the one the shortfall is argued against.

## 5. The DP-harming argument (argued, not asserted)

* **Branching is unchanged, exactly.** `SPAN_SHORTLIST` is untouched at
  160, the fill breaks only on `selected.len() >= SPAN_SHORTLIST` as
  before, and the `slots` walk reads `0..slots[k].len().min(cap)`. The
  per-span alternative count a segmentation can branch over is therefore
  the *same number* it was, `min(cap, |shortlist|)`, and the traversal's
  fanout is unchanged. Measured: pool 18,270 -> 18,276 and 18,936 ->
  18,925 are contents churn inside a fixed-width list, not a width change,
  and the three `approximate_pool_reaches_*` guards that key on breadth are
  two of three still green.
* **Every `SpanExtremes` extremum is still a max/min over the same 160
  candidates.** The extremes are computed *after* the sort, by folding over
  `selected`. The shortlist is still exactly `selected`, still at most 160
  entries, still drawn only from the span's own candidate set (test 3
  asserts the second half), so each extremum remains an extremum over some
  160-subset of the span's candidates and stays **admissible**: it is still
  a bound the enumeration below can attain or beat, never a claim the
  enumeration cannot reach. Nothing about admissibility depends on *which*
  160, only on there being 160 of them and all of them real candidates.
* **`min_cost` can only be tighter, and tighter is valid.** `min_cost` is
  a `min` over the shortlist. A stratified fill admits costlier-but-in-family
  words in exchange for cheaper ones, so the retained set's cost *floor*
  rises or stays. The DP uses `min_cost` as the best cost it may assume
  for this span; a **larger** `min_cost` is a strictly stronger statement
  about the optimum, and a bound that is stronger is still a bound as long
  as it is true of the retained set — which it is by construction, because
  it is a `min` over exactly the set the enumeration will choose from. It
  is not a *tighter-than-true* bound in the unsound direction: the failure
  mode for a DP relaxation is a bound that is *optimistic*, and this one
  can only move toward the truth, never past it. (It can, however, move so
  far that a span bound excludes a path the final scorer would have liked —
  which is a *quality* effect, not a soundness one, and is exactly what
  the red guard below is measuring.)
* **The suffix relaxation and the wall clock are untouched in structure.**
  No candidate is scored that the named passes did not already score: the
  fill re-orders an existing per-band `quality` sort of buckets the rule
  had already built and sorted, so the added work is a four-way
  apportionment over at most 4 bands and at most 60 slots. Wall clock on
  the two canonical cases: 1.045 s -> 1.039 s (case 1) and 1.145 s ->
  1.133 s (case 2), i.e. inside run-to-run noise.

## 6. The red fence — reported, not re-pinned

`cargo test --release --test corpus_integration -- --test-threads=2` on
this branch: **11 passed, 2 failed**.

* `approximate_finds_classic_madgab_resegmentation` — **pre-existing red**
  at this base, unchanged by this work.
* **`approximate_pool_reaches_matches_deep_in_a_span` — RED, and this
  branch made it red.** Message: `taco cat: "taco net" missing, so a match
  deep in a span's match list was not reached; pool had 15527 clues`.

Verified green at the pristine base in a scratch worktree on a scratch
branch (`/workspace/madgab-fillstrat-probe`, branch
`scratch/7b40d2-probe`, `CARGO_TARGET_DIR=/workspace/target-7b40d2-probe`):
base `3e821c3` gives **12 passed, 1 failed** — only the classic
resegmentation. So the guard's green is a real regression of this change.
**It is not re-pinned and its literals are untouched.**

**Why, in one line.** `net` is a candidate of `taco cat` at span `[6,8)`
with cost **0.2649745686**, which is code cost band **2** (`0.25..0.375`).
Under the old global-quality fill it was inside the top 160 by quality
(quality falls with cost, so a 0.265 word is comfortably inside). Under
the stratified fill the band-2 words are spent by band-2 `quality` and
`net` is not among the ones that allotment reaches, so it leaves the
shortlist and the pool loses it. The guard is measuring exactly the
property the fill gives up: cheap-end reachability.

**The trade, stated.** 623 -> 4 dropped cheap candidates, 43% -> 4.3%
worst-span share, one pool-reach guard red, and the printed top-50
unchanged. That is a real improvement bought with a real loss, not a free
win, and the right call is not to take it unilaterally.

**What a successor front has to try** (not implemented here, time-boxed):
keep the apportionment but floor the cheap end at what the global order
would have retained — e.g. cap the dearer bands' combined fill share (a
third of the fill, say) so band 0 and band 1 keep at least the slots the
global `quality` walk gave them, and spend only the remainder
stratified. That keeps the dear bands represented (the defect) without
letting a dear band evict a cheap word the pool-reach guards depend on
(the regression). Whether one third is the right number is a measurement,
not a guess, and the measurement is cheap: the same probe prints the
per-target dropped counts and the guard is a single test.
