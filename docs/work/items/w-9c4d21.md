# Derive the coverage reserve's depth and index range from the shape class
# and measured slot ambiguity instead of three fixed constants

## Context: why this mechanism and not another

The arms already fixed the numbers, so this front must not re-census them.

* [w-d4a90b](w-d4a90b.md): on the current head the requested wording is absent
  from the **entire** pool (17 827 candidates at `--top 50`, 13 498 at CLI
  default), so it has no rank. It is admissible (per-word costs
  `0.2 / 0.0 / 0.15 / 0.3695 / 0.4`, total `1.11951981` <= `1.5`) and scoreable
  at `0.79990129077367222`, i.e. `0.0978513` below the worst visible proposal.
  It is dropped **before the pool is formed**, so no scoring, admission,
  share-cap or cutoff change can surface it.
* Its per-slot ranks against the traversal's best index in its own slot's
  ranked list are **`7 / 0 / 13 / 99 / 11`** — exactly **one** coordinate (slot
  3, rank 99) is far out of reach; the other four are within or near the
  traversal's own opening width.
* [w-5f1c04](w-5f1c04.md), [w-be6d21](w-be6d21.md): the global emission budget
  is **unreachable by construction**, not short — `emit_allowance` is clamped to
  `LEXICAL_COMBINATIONS_PER_SEGMENTATION = 64` per segmentation, so 1x..256x of
  the budget is byte-identical output. Do not re-open the budget family.
* [w-8f3c61](w-8f3c61.md), [w-9d4e17](w-9d4e17.md): the visit-order and
  per-slot truncation families are refuted; the staged width widens **0 times**
  on multi-clause targets.
* [w-6f3a91](w-6f3a91.md) / [w-c1d3a7](w-c1d3a7.md): the adjacency operator is
  integrated and its bounded neighbourhood walk cannot promote the clue
  because it sits under ~1e4 better wordings of its own structure.

So the reserve is the last open lever, and it is open because of three
**fixed constants** rather than because of any property of the input:

1. `const EMIT_PROFILE_MAX_DEEP: usize = 3;` (`src/lib.rs:212`) caps how many
   slots of a profile may be deep at once. Four are needed here.
2. `sweep_index` (`src/lib.rs:~300`) places a shape class's members on a floor
   tied to the traversal's own opening (`LEXICAL_BRANCH_STAGE_0 = 10`) with a
   coprime per-member stride. That stride is what structurally cannot reach a
   high index in a specific slot.
3. `EMIT_PROFILE_RESERVE` is a fixed emission spend per segmentation, not
   derived from how ambiguous the slots actually are.

The general mechanism this item owns: derive (1) from the shape class's own
size and the number of slots, (2) from the **measured per-slot candidate-list
widths** the traversal already computes, and (3) from measured slot ambiguity
(e.g. the cost mass or list width each slot actually has) rather than from a
hand-picked constant. Every one of those inputs is a property of the search's
own state, so the change helps other inputs for the same reason.

## Hypotheses, in order

1. **Depth derived from the class, not fixed at 3.** A `k`-deep profile class
   has `C(depth, k)` members per sweep step, so a cap that grows with the
   shape class's own size (and is still bounded by named arithmetic) expresses
   the four-deep shape this input needs without naming it.
2. **Index range derived from the slot's own list width.** If the reserve's
   stride is scaled by the measured width of the slot it is displacing rather
   than by a global floor, a high-index member becomes reachable for exactly
   the slots that have deep lists.
3. **Spend derived from measured ambiguity.** If the reserve's emission
   allowance is a function of the slot ambiguity actually present, then a
   five-slot input with one expensive slot gets the emissions that slot needs,
   without a global budget increase (which is provably non-binding).

A refutation of all three, with the arithmetic, is an acceptable and useful
result — record it and route on the next gate.
