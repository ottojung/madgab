# The default approximate path's candidate pool is not run-to-run deterministic

## Goal

Make the deduplicated candidate pool the release binary's approximate mode
produces for one target byte-identical between runs of identical code, so a
membership count is a fact about the code rather than about the run. The
visible proposal list is already deterministic; the pool behind it is not.

## Why this matters beyond tidiness

Every reachability claim in this repository is denominated in *pool
membership*, and this item's admissibility rule
([w-2f7a10](w-2f7a10.md), inherited from [w-c4e8d7](w-c4e8d7.md)) says a
reachability claim counts only if it is membership of the deduplicated pool
the release binary actually produces on the default path. If that pool is not
reproducible, then a 0 -> 1 or a 3 -> 0 transition at a one-candidate margin is
not decidable, and a `true`/`false` per-witness column is not a measurement.

## Hypotheses worth discriminating, in order

1. **`RandomState`-seeded iteration order over a hash container** in a place
   that decides admission, retention or emission. The fix is to give that
   container a fixed-seed hasher or to sort its output before it is consumed,
   the same shape of fix `7faa74c` already applied to the `seen` set.
2. **A tie broken by arrival order** where two candidates score or cost
   exactly equal, so the sort is stable but the input order is not. The fix is
   a total order on the key rather than a stable sort over an unstable input.
3. **Parallelism.** If any phase is parallel, the nondeterminism is a race in
   collection rather than in ordering, and the fix is collection order, not
   hashing.

Hypothesis 1 is the cheapest to test and the most likely; a run of the same
binary under a fixed `RUST_HASH_SEED`-equivalent or a `FNV`/`Fx` hasher
temporary patch separates 1 from 3 immediately.

## Scope and collision boundary

This item owns the *reproducibility* of the pool, not its size, its ranking or
its breadth. It may change hashing, key derivation and collection order, and it
may tighten `tests/approx_determinism.rs` to assert over the pool. It must not
touch `EMIT_PROFILE_MAX_DEEP`, `coverage_tuples`, `sweep_index`, the emission
budget accounting, `axes::*`, `select_diverse`, the share cap or
`STRUCTURE_FLOOR`, and it must not move any retention constant to make a
number look better. While [w-2f7a10](w-2f7a10.md) has live fronts in
`coverage_tuples`, this item must not contend on that file.

## Completion criteria

1. The defect is **localised by line**: the exact container, sort or phase
   whose non-determinism lets a run-to-run delta into the pool, with a
   reproduction that shows the same build producing two different pools.
2. **A landed, general fix** with no target-specific, phrase-specific or
   input-specific case, and no `MADGAB_*`/`ZZ_*`/`zz_*` scaffolding on the
   branch.
3. **Proof of reproducibility**: at least 20 consecutive runs of the release
   binary on the current head over at least four targets produce an identical
   deduplicated pool count, and the previous behaviour is shown to have been
   non-identical on the base so the test is a guard and not a restatement.
4. **`tests/approx_determinism.rs` tightened** to assert pool-level
   reproducibility as well as visible-proposal determinism, naming no target
   phrase.
5. `cargo test --release --lib`, `--test corpus_integration`,
   `--test exact_determinism` and `--test approx_determinism` reported.
   `cargo fmt`, `cargo clippy` and doctests do not exist on this host; see
   [../../environment-notes.md](../../environment-notes.md). Do not claim them.
6. `recognize speech` -> `wreck a nice beach` still generated and visible, and
   `approximate_finds_classic_madgab_resegmentation` not made worse: it is red
   on the base and must stay red, not green by accident and not newly failing
   for a different reason.
