# Remove the remaining per-candidate allocations from approximate search

## Goal

Continue the behaviour-preserving constant-factor work of
[w-7fa26c](w-7fa26c.md) into the invasive half it deliberately handed off
(P5), now that the cheap wins are integrated and a fresh behaviour lock
exists.

## Context

`madgab-approx-runtime` landed as `d8e14cd` on
`post-milestone-acceptance` (agent `a1b2c304`, item
[w-7fa26c](w-7fa26c.md)). Its post-change profile of
`--approximate --top 20` on `congratulations on your promotion`
(`generate_approximate` total 5.22 s at the time) attributed the
remaining cost to:

- the final prune step, dominated by *cloning* the retained `Partial`s
  (each clones a `Vec<ClueWord>` of `String`s plus the path `key`);
- the dedup and key-sort stages, which are `String`-hash and
  `String`-compare bound;
- `extend_fuzzy` (942 280 calls for that target), which clones the whole
  word and cut vectors and grows `key` with `format!` — O(W^2) per path.

The proposed fix is `Rc`-based `Partial` (or interned path keys) so the
beam shares structure instead of copying it. That is the restructuring
the earlier brief told the agent to hand off rather than attempt.

The behaviour lock is `approximate_output_is_locked` in
`tests/corpus_integration.rs`, re-baselined on the integrated tree during
the same pass. `cargo test --release --lib`,
`--test corpus_integration` and `--test exact_determinism` are the
validation commands (`cargo fmt`, `cargo clippy` and doctests do not
exist on this host; see [../../environment-notes.md](../../environment-notes.md)).

## Completion criteria

- Output is bit-identical to the pre-change binary across a spread of
  targets and configurations, demonstrated with a reproducible
  comparison recipe in the handoff and guarded by
  `approximate_output_is_locked`.
- `Partial` state is shared rather than copied on the beam's hot path, or
  the agent has measured and reported evidence that it is not worth it.
- `cargo test --release --lib`, `--test corpus_integration` and
  `--test exact_determinism` show no new failures.
- Before/after wall clock reported for every configuration measured, with
  the known noise caveat of this shared host.
- No phrase-specific hard-coding, and no scoring-semantics change: this is
  a constant-factor item, and the axes in `axes::*` must not move.

## Handoff / notes

Not started. Base the branch on the current `post-milestone-acceptance`
(`d8e14cd` or later), not on `d46d154`: the scoring, selection and P1-P3
work all landed since, and comparing against the old base would show
intended scoring changes as regressions.

Heads up on the tree this lands on: the retain/sort path now sorts
retained indices against the cached `metrics` vector, and the beam
retention is deterministic (the exact-determinism front, w-5d03af). Any
`Rc`/interning change must preserve that determinism — interned keys are
only safe if equal keys still compare equal and the tie-break order does
not depend on allocation addresses.

This front is independent of the reachability front
([w-6d1f45](w-6d1f45.md), agent `b1c2d02` running in
`/workspace/madgab-phonetic-reach`) and of the milestone blocker it
owns. Keep the change separable: if a hunk has to choose between
behaviour and speed, behaviour wins and the conflict is handed back.
