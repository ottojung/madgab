## What is broken

On this host the usual POSIX tooling is absent. Measured, not assumed:

- `/usr/bin` contains only `env` and `sh`.
- No `git`, no `ls`, no `cat`, no `grep`, no `sed`, no `head`, no `date`,
  no `nohup`, no `timeout`, no `sleep`, no `tr`, no `wc`. Resolving any of
  them on `PATH` fails, including by absolute path.
- Present and working: `node`, `npm`, `cargo`, `rustc`, `elan`, `ssh`,
  and the `antonina`, `lubko-*` and `openclaw` wrappers in
  `~/.local/bin`. `cargo` reaches the registry and builds metadata normally
  (`cargo metadata` succeeds), and the prebuilt
  `target/release/madgab` (30,352,616 bytes) runs.
- Consequently `git status`, `git log`, `git diff`, `git worktree`,
  `git merge`, `git commit` and `git push` are all unavailable. **No branch,
  no commit, no push and no integration is possible on this host.** A
  coordinator pass here must not pretend otherwise.

**A later pass must not read `idle` as "available" and must not conclude

## Resolution (coordinator pass 2026-09-27T01:57Z, coord-5c1de): not an outage, a `PATH` gap

The host was never broken. The toolchain exists, it is just not on the
coordinator shell's `PATH`.

- `PATH` as inherited by the coordinating shell is
  `/home/lubko/.openclaw/tools/node-v24.21.0/bin:/usr/bin:/bin:/command:/usr/local/bin:/home/lubko/.local/bin`,
  and `/usr/bin` and `/bin` contain **only** `env` and `sh`. That is exactly
  why the previous pass saw no `git`, no coreutils and no `date`.
- `GUIX_PROFILE` is exported (`/gnu/store/89f20yrghd9ld6mc6a717rcj4mwshfvw-profile`)
  and `$GUIX_PROFILE/bin` contains `git`, `date`, `ls`, `cat`, `grep`, `sed`,
  `head`, `tail`, `wc`, `tr`, `timeout`, `nohup`, `sleep`, `cp`, `mv`, `mkdir`,
  `python`-adjacent tooling and the rest of coreutils.
- The fix for every later pass is one line, before anything else:

  ```sh
  export PATH="$GUIX_PROFILE/bin:$PATH"
  ```

With that exported, `git` works normally, and the Antonina control that
failed with exit 127 in the previous pass now **succeeds**:

| agent | cwd | prompt | result |
|---|---|---|---|
| `c0ffee2` | `/tmp/opencode/ctrl` | `Reply with the word OK and nothing else.` | **succeeded, replied `OK`, exit 0** |

`c0ffee2` is the same control as the failed `c0ffee`. So exit 127 was the
agent runtime inheriting the truncated `PATH` and failing to find a binary it
needs, not a missing runtime.

**Instruction for every future pass:** export
`PATH="$GUIX_PROFILE/bin:$PATH"` before concluding that anything is missing
from this host. Do not file another host-outage item without running that one
export first, and do not re-file agent briefs that a prior pass already
briefed. If a future pass really does fail, print `echo $PATH`,
`echo $GUIX_PROFILE` and `ls $GUIX_PROFILE/bin | head` as the first evidence.
