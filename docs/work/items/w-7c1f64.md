# Production-path emission coverage: why the canonical five-word alignment is never proposed

## Goal

anywhere, the question that three successive fronts have each answered
differently: for `It's just a stupid game`, is the alignment whose
resegmentation is `hits justice dupe hid came` ever a candidate that
`madgab --approximate --top 50` could print, and if not, the exact
production condition that prevents it?

Then either land a **general** change that makes the production search emit
it, or deliver an implementation-ready specification with the budget
arithmetic for the recommended design.

The durable fact is not any single measurement, it is that this
repository's measurements on this question have reversed three times,

wider budget* was mistaken for the production path:

## Method: the production path is the only admissible evidence

This is the fence that matters most, and it exists because it has already
cost this repository three reversals.

- Every claim must be reproducible from the **release binary at default
  configuration** (`./target/release/madgab --approximate --top 50 ...`) or
  from the public library API at its default settings. State which.
- A scratch harness that widens any of `SPAN_SHORTLIST` (160),
  `SEGMENTATION_KEEP` (256), `LEXICAL_COMBINATIONS_PER_SEGMENTATION` (64),
  `LEXICAL_BRANCH_STAGE_GROWTH` (4), `LEXICAL_HEAP_POP_LIMIT` (4000),
  `LEXICAL_GLOBAL_EMISSION_BUDGET`,
  `LEXICAL_GLOBAL_POP_BUDGET`, `EMIT_PROFILE_RESERVE` (16) or the total
  cost budget **may not be cited as evidence about the production path**.
  It is legitimate to use such a harness to learn what the lattice
  *contains* — that is a different question and must be labelled as one.
- `MADGAB_TRACE_PHRASES` is an existing trace facility, not a new
  env-var knob. New knobs and `eprintln!` probes must stay on `scratch/*`.
- The two questions must be reported separately and every time:
  **(a) is the alignment in the lattice?** and **(b) is it in the
  production candidate pool?** A "yes" to (a) with a "no" to (b) is the
  expected and useful answer, and it localises the work to emission.
- If a measurement needs a rebuilt binary to be trusted, force the rebuild
  and say so. `git bisect` on this tree is untrustworthy without one,
  because boundary commits are docs-only and cargo reuses the previous
  binary — that mistake has already produced a bogus "first bad commit is
  a docs commit" conclusion.

## Fences

- No phrase-specific hard-coding, and no special case for these two
  sentences, their clues, their words, or any substring of them. Any
  production-code mention of them is a defect even in a comment.
- No `zz*` probe file, no `eprintln!` probe, no new env-var knob and no
  phase timing on the branch that reaches the accumulation branch.
- Do not re-open a cost, pronunciation, dictionary, `GAP_COST`,
  `LEXICAL_BRANCH_KEEP` or `SEGMENTATION_KEEP` front as a *number*: those
  are closed by measurement in [w-c4d7e8](w-c4d7e8.md),
  [w-1c3e77](w-1c3e77.md), [w-6f2b18](w-6f2b18.md),
  [w-7b41d2](w-7b41d2.md) and [w-b2e5c4](w-b2e5c4.md). What is open is
  **coverage**: why the emission budgets allocate their budget where they
  do, and whether a budget-derived allocation that provably reaches
  alignments of this class exists at the current wall clock.
- Do not relax, re-baseline or `#[ignore]` a test to make something pass.
  `approximate_output_is_locked` will change if the objective moves; if it
  moves, re-measure it on the merged tree and record the before/after
  honestly. In particular, do not describe a re-locked list as unchanged
  when any phrase in it differs.
- Canonical case 1 must not regress: `wreck a nice beach` must remain in
  the printed proposal set for `recognize speech`.
- `cargo fmt` and `cargo clippy` do not exist on this host; do not report
  them as run. See [../../environment-notes.md](../../environment-notes.md).
  `git` is only on `PATH` via `$GUIX_PROFILE/bin` — export it first, or
  every git command fails with "not found", which has already been
  misdiagnosed as an outage once.
