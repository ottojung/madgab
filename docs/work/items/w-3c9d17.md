## 1. Admissibility — the central claim, verified independently

**`n` is not a word count, and that is what makes the fix correct.** In
`generate_approximate`, `n = chars.len()` where `chars` is the *target's IPA*
(`src/lib.rs:822-823`). The scorer divides by exactly the same quantity: `let
total_len = target_ipa.chars().count();` (`src/lib.rs:2817`), and
`let cost_per_phone = self.sub_cost_total / total_len.max(1) as f64;`
(`src/lib.rs:2717`). So the bound's `n.max(1)` and the scorer's
`total_len.max(1)` are the same integer, the target's phone count. (The brief's
phrasing "is `n` the scorer's word count" invites a wrong answer; the right
answer is that `n` is the scorer's *denominator*, not its word count — the
scorer has no word count in this term at all.) The `n == 0` early return at
`src/lib.rs:824-827` means `n >= 1` here, so the `.max(1)` is inert but
harmless and matches the scorer term for term.

**The inequality.** Let `C*` be the total edit cost of any completion reachable
from a prefix, `C_min = cost + suf_min_cost[k]` the cheapest such cost
(`suf_min_cost` is a sum of per-slot minima, so `C_min <= C*` for every
completion — that much was already sound), `P = n.max(1)`, and `c = 0.30 =
axes::SIMILARITY_COST_PER_PHONE`. The scorer's similarity term is
`S(C) = (1 - C / (P c)).clamp(0, 1)` and the bound's is
`B = (1 - C_min / (P c)).clamp(0, 1)`. Since `x -> (1 - x).clamp(0, 1)` is
non-increasing in `x`, and `C_min <= C*` gives `C_min/(Pc) <= C*/(Pc)`, we get
`B >= S(C*)`. Multiplied by `axes::SIMILARITY = 0.25 > 0` and added to the
other relaxed-upward terms, the bound is an upper bound on the combined score
for **every** `n >= 1`, including:

* **the flooring case.** If `C* >= Pc` the true term is 0 while the bound is
  `(1 - C_min/(Pc)).clamp(0,1) >= 0`. Still admissible; the bound can only sit
  above.
* **the saturating case.** `B <= 1` always because of the outer `.clamp(0.0,
  1.0)`, and the scorer's term is also `<= 1`, so the bound cannot exceed the
  axis maximum. There is no case where the bound exceeds 1.0 in a way the
  scorer would clamp away — the clamp is inside the same axis, as it is in
  `metrics`.
* **the "is it only a bound at its floor" question.** It is not. There is no
  floor anywhere in the argument. The correct-denominator case is *stricter*
  than a floor, and it holds for all `n`, not only where the scorer's term has
  saturated.

**The old form was indeed inadmissible, and the comment's arithmetic is
right.** `B_old = (1 - C_min/4).clamp(0,1) >= S(C*)` requires
`C_min/4 <= C*/(Pc)`, i.e. for the tight case `Pc <= 4`, i.e.
`n <= 4/0.30 = 13.33` phones. The real canonical targets are far longer
(`recognize speech` is 24 phones; there is a fixture at `src/lib.rs:5852`
using `total_len = 24`), so on essentially every real target the old bound
penalised cost *more* than the scorer does and sat below the score of
completions it was meant to dominate. The claim that this invalidates the
heap key and the coverage reserve's "best admissible position" argument is
correct: a key below an achievable score can pop a node whose descendants
contain a better-scoring wording than a node it did pop.

**Net:** item 1 of my brief passes. The bound is now genuinely admissible,
for all `n`, on the axes actually used (`SIMILARITY`, `NOVELTY`, `WORD_NOVELTY`,
`FAMILIARITY`, `CLOSED_CLASS`, `RHYTHM`, `SHAPE` — the eighth axis, `PUNCH`,
is `+ w*(v-1) <= 0` and the bound omits it, which is upward-relaxed and
therefore fine; that omission is pre-existing, not introduced here).

   nothing beyond "the pool is non-empty". The commit's own inline comment
   concedes the point — "the reach is unchanged" is asserted while the
   literals that evidenced it are replaced, and the replacements are claimed

3. The pinned *claim* is expressible as a property, and the item asks for

   shape a retry should take, and it is a strictly better test than the one it
   replaces, because it stops being sensitive to which sample member the
   reserve happens to spend on while keeping the reach claim honest.

## 5. Defects to carry into the retry

1. **Red fence.** Two pinned regression tests fail (§4). Criterion 5 is not
   met. Do not land over this.
2. **The test edit is forbidden and wrong** (§4, above). Revert
   `tests/corpus_integration.rs` in `/workspace/madgab-emitbound-5b1e93` and
   do not commit `examples/zzz_dump_pool.rs`.
3. **Half-fix: three sibling bound sites still use the stale `/4.0`
   normaliser** and are inadmissible for `n > 13.3` phones by the same
   arithmetic: `complete_span_score` (`src/lib.rs:3463`) and
   `span_score_bound` (`src/lib.rs:3517`). The latter is documented as
   "Admissible upper bound on the final score of *every* alignment reachable
   through a span path" and is demonstrably not one. Neither takes a phone
   count, so a consistent fix has to plumb the target's `n` (or the axis
   itself) into both. The `structural_bounds_dominate_the_real_scorer` lib
   test passes, which is itself a finding: it is not catching this.
4. **Comment overstates the evidence.** "this form is above it on 14 of 14, on
   every one of 11.2 million wordings checked" — I did not reproduce that
   11.2M sweep, and the claim cannot be true as stated for *all* wordings if
   the old form is measured below the real score on 12 of 14: the two forms
   are not ordered against each other everywhere, and the assertion as
   phrased invites exactly the reading the author wants to avoid. The
   derivation in §1 is what makes the claim true; the measured sentence should
   be narrowed to what was measured or dropped in favour of the derivation.
5. Not a defect but recorded: `quantized(bound(..))` is the actual heap key.
   Whatever rounding it applies is now applied to an admissible bound; it was
   already there and I did not test it, but a key that can round *down* below
   an achievable score reintroduces a whisper of the old defect. Worth a
   stated check on the retry.
