# Accepted state of MadGab — 2026-09-27

The current MadGab implementation is **accepted for release** as of September 27, 2026 (America/Vancouver). The preceding approximate-search programme made substantial general improvements to matching, segmentation, bounded enumeration, scoring, result diversity, runtime, and observability. Further autonomous research is paused unless a human explicitly reopens it.

## What is accepted

The accepted implementation is the integrated state of the former `post-milestone-acceptance` branch at release time. It is intentionally general: none of the canonical examples is hard-coded into production logic.

The current approximate search:

- uses indel-aware fuzzy phonetic matching over the target IPA stream;
- separates structural segmentation retention from lexical choice;
- retains bounded per-span lexical portfolios and a bounded set of segmentations;
- enumerates lexical combinations under explicit frontier/emission budgets instead of taking an unbounded Cartesian product;
- reserves bounded search capacity for structurally/depth-diverse candidates;
- scores complete clues on phonetic similarity, novelty, familiarity, rhythm, shape and related quality signals, including the worst individual word rather than only aggregate edit cost;
- applies structure-aware final selection to avoid a result list made entirely from one segmentation family.

On the accepted integrated head, the two canonical release tests take about 1.8 seconds each in an already-built release test binary on `marceline-dev`.

## Canonical status

### Working

`recognize speech` → `wreck a nice beach`

This clue is generated by approximate mode and passes the repository's top-50 acceptance regression. Recent scoring work also moved it to roughly pool rank 8–9, although the shipped default top-10 presentation can still be affected by structure-diversity selection.

### Known unresolved limitation

`It's just a stupid game` → `Hits Justice Dupe Hid Came`

The exact classical clue is **not generated by the current production candidate pool**, so its top-50 acceptance regression remains red. This is an accepted known limitation, not an accidental omission from the release notes.

The investigation established that:

- all five desired words are present in the default corpus and fuzzy lexicon;
- their pronunciations are available;
- the complete sequence is feasible in the fuzzy phonetic lattice and fits the normal total edit budget;
- removing the rarity bound and expanding the vocabulary from about 50k to about 281k words still does not make the phrase appear;
- simple changes to per-slot order, retained set, width, shortlist fill, reserve placement, emission limits, adjacency substitution, and scalar score reweighting were either measured negative or bounded by the combinatorics;
- widening the old product-style traversal enough to reach the needed deep lexical coordinates is prohibitively expensive.

The remaining problem is therefore a genuine **whole-path enumeration problem**. If this work is reopened in the future, the most promising direction is a qualitatively different complete-path algorithm (for example a compact pronunciation DAG with k-best / A*-style whole-path search or a strong backward suffix heuristic), rather than another widening of the existing Cartesian-prefix traversal.

## Operational status

The autonomous MadGab improvement queue is paused. Repository work items that were still `open`, `working`, or `blocked` at this acceptance point are superseded by this release decision; their reports remain valuable research history. Scheduled orchestrators must not create new MadGab work or resume those items unless a human explicitly asks to reopen development.
